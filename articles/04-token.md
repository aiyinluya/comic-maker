# Token 是什么:AI 世界的人民币

> 码事漫谈 · AI 科普系列

## 引入

用 AI 的 API 按量付费时,账单单位不是"一句话"、不是"一篇文章",而是 **token**。买会员时说的"每月 100 万 token",也是它。

很多人到这里就含糊了:token 到底是什么?为什么我发一句中文,扣的 token 好像比英文多?这篇文章用三分钟把它讲透--因为不理解 token,你就永远算不清 AI 的账,也管不好上下文(上一期的伏笔又出现了)。

## Token:AI 眼里的"字"不是你的字

大模型不认识"字",它认识 token。**token 是模型处理文本的最小单位**,由模型的分词器(Tokenizer)把文本切出来。

关键在于:**切法不一定按词,更不按字**。

- 英文:一个常见单词通常就是一个 token("hello" 1 个),长词会被拆开("extraordinary" 可能是 3-4 个);
- 中文:常常一个字甚至半个词就是一个 token("人工智能"可能是 4 个 token,"你好"可能是 1-2 个,取决于分词器);
- 数字、标点、空格:也都算 token。

这就是为什么**同样一段话,中文通常比英文多花 1.5 到 2 倍的 token**--不是服务歧视中文,是切分粒度天然不同。

## 自己动手:一句话有多少 token

拿这句常见的问候算一笔账:

> "你好,请帮我总结这份报告。"

按主流分词器的粗略规则:"你好"≈1-2 个 token,","≈1 个,"请"≈1 个,"帮我"≈1-2 个......整句下来大约 **10-14 个 token**。而同样意思的英文 "Hi, please summarize this report." 大约只要 **7-8 个 token**。

精确数字取决于各家模型的分词器(OpenAI、Anthropic、国产模型各有各的切法),所以**别猜,用各家官方的 tokenizer 计算器**--写代码前先量一下,是省钱的第一步。

## Token 怎么计费:进出都要钱

API 账单里 token 分两种:

- **输入(input/prompt)**:你发给模型的一切--问题、附带的文档、历史对话、系统指令,全算;
- **输出(output/completion)**:模型回复的内容,通常比输入贵 3-5 倍。

## 动手算一笔:长对话的成本曲线

最容易踩的坑是**每次对话都重发全部历史**。API 是无状态的:模型不记得上一轮说过什么,想让对话连续,客户端就得把整个历史再发一遍。聊到第 20 轮时,你付的是 20 轮全部历史的输入费--这就是为什么聊得越久越贵。

用主流模型每百万 token 几美元到几十美元的公开定价量级,做一道理想化算术:假设每轮新增 500 token,第 10 轮要重发 5000,第 50 轮要重发 25000......50 轮下来仅输入就累计约 63 万 token,其中大部分是重复的旧历史。如果每 10 轮把历史压缩成 200 token 的摘要,累计能降一个数量级--这正是上下文工程(压缩历史、隔离任务)能真金白银省钱的原理。

## 上下文窗口：AI 的饭量也有上限，但不等于胃口好

模型一次能处理的 token 总量就是**上下文窗口**。百万 token 窗口的模型现在很常见，但两个误区要先破：

1. **装得下 ≠ 用得好**：窗口大不等于注意力均匇。有研究测过“大海捞针”式任务：把一句关键信息埋在百万 token 的中间，模型对中段信息的回忆准确率明显低于头尾——“中间迷失”是公认现象。所以长文档任务照样要做检索和分段，而不是全量硬塞；
2. **大窗口 ≠ 免费大胃王**：窗口越大，满载时的成本越高，响应也越慢。“反正窗口大就随便塞”是典型的成本陷阱。

给普通用户的实用结论：长文档别整本扚，先分段或摘要；付费 API 场景下，控制上下文长度就是直接控制账单。

读完这篇，再看上一期讲的“上下文工程”，会发现它们其实是同一枚硬币的两面：

- **上下文窗口**告诉你：饭量有限，塞太多会消化不良（注意力稀释）；
- **Token 计费**告诉你：饭量还按粒收费，塞多少付多少。

所以上下文工程的每一个手法，本质上都是在做 token 的预算管理：检索是“只买需要的食材”、压缩是“把剩菜做成高汤”、隔离是“每桌客人单点”、持久化是“租个冷库”。理解了 token 的计量方式，上下文工程的那些手法就不再是抽象名词，而是四条省钱路径。

给不同读者的两句话：普通用户记住“中文更费 token、长对话会滚雪球”；开发者记住“量化每一轮的输入输出，先用官方 tokenizer 测再上线”。

## 要点小结

- **token = 文本的最小处理单位**,按分词器切分,中英文粒度不同,中文通常更"费";
- 计费**进出都算**:输出单价是输入的数倍,历史对话每轮重发;
- **上下文窗口 = 单次处理的 token 上限**,装得下 ≠ 用得好;
- 实操三件事:用官方 tokenizer 量化、压缩历史、给长任务做隔离。
