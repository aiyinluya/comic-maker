# 豆包 2.1 Pro 0915：AI 从 "陪聊" 到 "干活" 的一步

> 码事漫谈・AI 科普系列・配套漫画《豆包 2.1 Pro：0915 新版强在哪？》

## 引入

2026 年 9 月 16 日，火山引擎宣布 Doubao-Seed-2.1-pro 的 **0915 新版**全量上线火山方舟，豆包工作、TRAE 同步接入，企业无需更换 API 节点即可使用。距离 6 月 FORCE 大会上 Seed 2.1 首发，刚好过去三个月。

这一版没有花哨的发布会，四个升级方向却指向同一件事：**让模型从 "会聊天" 变成 "能交活"**—— 不仅要回答得对，还要看得懂图、查得到证据、扛得住连续几十个小时的任务，而且更便宜。

## 一、会看图：草图、录屏、设计稿，直接变成能跑的代码

这次更新被官方排在第一位的能力，是**多模态编程**。

过去的代码模型只认文字，可人类表达一个界面时最自然的方式是画图 —— 在餐巾纸上勾几个方框、录一段操作视频、丢几张设计稿。纯文本模型面对这些毫无办法，相当于 "天然缺一条腿"。

0915 版补上了这条腿：

* 手绘草图、操作录屏、设计稿，可以直接转成前端代码和游戏逻辑；

* 关键是，它产出的**不是一张界面截图，而是能点击、能运行的真代码**，还能端到端跑完 "理解需求 → 改代码 → 运行命令验证测试"；

* 一个有说服力的案例：一套约 28 万行 Java、几乎没有文档的老 ERP 系统，模型仅凭一段操作录屏和几张草图，就开发出了能跑通业务流程的移动端页面。

## 二、会搭 3D，也敢啃几十万行的大项目

只会写网页还不够，这一版在三维和大型工程上同样露了一手。

* **四张设计图，还原一个可交互的 3D 庭院**：先搭基础结构，再做水体和植被，最后加上风霜雨雪四季变化，全程可以交互；

* 面对开源游戏 Luanti（原名 Minetest，约 38.7 万行代码、上万个真实历史 Issue），模型调度多个子 Agent **连续运行了近 36 小时**，逐个处理 Issue，最终 **83% 的任务达到了可合并的标准**。

连续工作 36 小时、八成多任务达标 —— 这已经不是 "帮我补全一行代码" 的助手，而是一个不知疲倦的初级开发团队。

## 三、会干活，还敢为结论负责

Agent 真正让人不放心的地方，从来不是 "干得快不快"，而是 "说得对不对"—— 一本正经地编造（幻觉）是这类系统的老毛病。

0915 版的做法是把调研做成一条**有证据链的流水线**：

* 一次任务可以调度 **500 多个子 Agent**，并行检索上千个网页；

* 证据必须溯源，优先采信权威信源，还要做时效判断和交叉核验；

* 每条结论只能归入四种状态：**有证据支持 / 有证据反驳 / 证据矛盾 / 证据不足**，只许引用已登记的证据，连公关稿都不能单独作为依据。

官方演示过一个硬核案例：核实某车企 "巴西超级工厂 15 个月建成投产" 的说法，子 Agent 们调出了海事 AIS 滚装船的航迹、当地的岗位变化数据、以及卫星时序影像交叉比对，最终产出一份数十页的英文财报尽调报告。

## 四、看得懂长视频，而且更便宜

另外两项升级藏得比较深，但都很实在：

* **长视频理解**：可以一次处理两小时以上的视频，跨帧定位证据、对照作业规范辨认操作是否合规，直接产出解说稿、片段定位和字幕；

* **Token 效率**：图像和视频推理的 Token 消耗比上一代**降低 30% 以上**，推理轮次和工具调用次数也同步下降。官方给的说法是四个字：**加强不加价**。

## 从陪聊，到干活

把四件事放在一起看，方向异常清晰：**草图和录屏是新的编程界面，证据链是新的职业底线，长程任务和更低的成本是新的生产力边界。**

过去是人去学习机器的语言 —— 学命令、学语法、学怎么把需求翻译成提示词；现在轮到机器去看懂人的表达 —— 你的涂鸦、你的录屏、你的图纸。模型不再只是对话框里那个陪你聊天的角色，而开始像一个能接任务、能交结果的同事。

这，正是 0915 这一版最值得记住的地方。

## 要点小结

* **多模态编程（本次首位）**：草图、录屏、设计稿直接转可运行代码；28 万行无文档老 ERP 也能照录屏补功能；

* **3D 与大型工程**：4 张设计图还原可交互 3D 庭院；Luanti 38.7 万行代码、近 36 小时、83% 任务达可合并标准；

* **可信调研**：500+ 子 Agent、上千网页、证据溯源与交叉核验，结论分四态，幻觉大幅收敛；

* **多模态理解 + 成本**：一次处理 2 小时以上长视频；图像 / 视频推理 Token 降 30% 以上，"加强不加价"。
