# 上下文工程：Agent 的大脑管理术

> 码事漫谈 · AI 科普系列

## 引入

2023 年，人人都 chatGPT 学一个新词：提示词工程——怎么把话说好，让 AI 听懂。2026 年，另一个词正在取代它：**上下文工程（Context Engineering）**。

区别在哪？提示词工程琢磨的是"这一句话怎么写"；上下文工程琢磨的是"**AI 在回答之前，脑子里到底装了什么**"。前者是修辞学，后者是信息管理学。做简单问答，前者够用；做 Agent（能自主干活的 AI），后者是生死线。

## 先搞懂：什么是"上下文"

大模型有个硬约束叫**上下文窗口**：它一次能"看见"的内容是有限的，可以理解成 AI 的工作记忆。你发的消息、它读到的文档、之前对话的历史、工具返回的结果——所有这些东西拼在一起，才是 AI 回答时的完整"视野"。

问题来了：

- 塞得太少，AI 缺信息，开始瞎猜（幻觉的来源之一）；
- 塞得太多，关键信息被淹没在噪音里，AI 反而答不准；而且 token 消耗翻倍，成本和速度都遭殃。

**上下文工程，就是决定"往 AI 脑子里放什么、不放什么、什么时候放"的学问。** Manus（曾是全球瞩目的通用 Agent 产品）团队复盘时说过一句大实话：模型再强，也替代不了对上下文的管理。

## 四个核心手法

业界把上下文工程拆成四个基本动作，正好对应人类的记忆策略：

1. **检索（Retrieval）**：不把整本书塞给 AI，只在需要时查出相关段落。RAG 就是这个思路的代表作——代表作就是 RAG：先翻资料，再回答。
2. **压缩（Compression）**：对话太长时，把早期内容总结成摘要。像人写工作日志：细节可以忘，结论要保留。
3. **隔离（Isolation）**：把不同任务塞进不同的"脑子"。多智能体协作就是这么来的——研究员 Agent 和写作 Agent 各有各的上下文，互不污染（是一个独立的大话题）。
4. **持久化（Persistence）**：把关键信息写进外部存储（文件、数据库），下次要用再取回来。Agent 能"记住"你的偏好、接着昨天的工作干，靠的就是它。

这四个手法没有高下之分，成熟 Agent 都是组合拳：该检索的检索、该压缩的压缩、该隔离的隔离、该持久化的持久化。

## 一个真实场景

假设你让 Agent"整理上周的会议纪要并邮件发给团队"。它的工作记忆里应该装什么？

- 需要：纪要原文（检索来的）、邮件格式模板（持久化存储里的）、你的收件人列表；
- 不需要：上周你让它查天气的记录（压缩或丢弃）、整个文件系统的目录树（隔离到文件管理子任务里）。

 arrangements 错一项，轻则邮件发错人，重则 Agent 在几十万字的检索结果里"迷路"，半小时不产出。**Agent 的上限，往往不是模型的上限，而是上下文工程的上限。**

## 和提示词工程的关系

不是替代，是包含。提示词工程管"一句话怎么写"，上下文工程管"整句话境怎么配"——提示词只是上下文的一部分。打个比方：提示词工程是把菜谱写好，上下文工程是把整个厨房配齐（食材、火候、顺序、谁掌勺）。

所以 2026 年招"提示词工程师"的少了，要"上下文工程师"的多了——后者是给 AI 搭工作环境的人。

## 新手常犯的三个错

理解了四手法，还要避开三个高频误区：

1. **把历史全量硬塞**：“AI 不记得”就让客户端每次把全部历史重发——简单粗暴，但 token 成本随轮次平方级增长，且关键信息反而被冲淡。正确姿势是压缩：早期轮次总结成几句结论再带上；
2. **资料整本扚进去**：“上下文窗口够大”就恨不得把整个文档库复制进去。窗口大不等于注意力均匇，塞得越多，每条信息的“存在感”越稀薄。正确姿势是检索：只取与问题相关的段落；
3. **忘了给系统提示留位置**：任务规则、输出格式这些“必须每次生效”的信息，应该固定放在上下文最前面，而不是混在对话里靠模型自己找。

三句话总结：**该检索的别硬塞，该总结的别原封，该固定的别乱放。**

## 要点小结

- **上下文窗口 = AI 的工作记忆**，有限且有成本；
- **上下文工程 = 决定 AI 回答前"看见什么"的信息管理学**，正在取代提示词工程成为核心技能；
- 四个基本手法：**检索、压缩、隔离、持久化**；
- Agent 的上限常是上下文工程的上限：模型强不如"喂得对"。
