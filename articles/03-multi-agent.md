# 多智能体协作:一个 Agent 是员工,一群 Agent 是公司

> 码事漫谈 · AI 科普系列

## 引入

让一个 AI Agent 帮你写一份市场调研报告,它可能会:查资料查到一半忘了主题、把大纲和正文搅在一起、写到第三千字开始重复自己。不是模型不行--是**一个人的脑子装不下一个团队要装的东西**。

于是行业把思路从"造一个更强的 Agent"转向"让一群 Agent 分工合作"。这就是**多智能体协作(Multi-Agent System,简称 MAS)**:2026 年 Agent 落地爆发年里,几乎所有复杂的 Agent 产品背后都是它的变体。

## 为什么单个 Agent 会"累趴"

上一期讲上下文工程时说过:Agent 的能力上限常是上下文的上限。单个 Agent 处理复杂任务时,三个坑几乎必然踩:

1. **上下文爆炸**:查资料、写代码、改格式的历史全堆在一个工作记忆里,关键信息被淹没;
2. **角色混乱**:既要当研究员又要当编辑,两种"性格"互相打架;
3. **单点故障**:一个环节出错,整条链报废,没有纠错者。

人类公司的解法是分工。多智能体照抄了这份答案。

## 一支 Agent 团队长什么样

一个典型的多智能体系统,是把复杂任务拆给不同角色的 Agent:

- **规划者(Planner)**:接需求、拆任务、派活儿,像项目经理;
- **研究员(Researcher)**:只负责查资料,上下文里全是检索结果,干净专注;
- **执行者(Worker)**:只负责写代码或写文稿,拿到的是研究员提炼后的精华;
- **审查者(Critic)**:专职挑错,对照需求逐项验收--它不看过程,只看结果对不对。

## 一个真实案例:调研报告团队

拿"写一份竞品调研报告"举例,看多智能体怎么分工:

- **规划者**接需求后拆出四个子任务:确定竞品清单、逐个调研、汇总对比、成稿排版;
- **研究员**们并行开工,每人只负责一家竞品,各自上下文里只有自己那家的检索结果,互不干扰;
- 产出是格式化的竞品卡片:定位、功能、定价、口碑四个字段,字段缺失就标"无数据";
- **汇总者**把卡片合并成对比表,发现某家信息不足,只针对那家向研究员追问一次;
- **审查者**最后验收:对比表是否覆盖全部竞品、结论是否有出处,不达标整体打回重做。

整个过程里没有一个 Agent 需要了解全部细节--这就是它能保持"专注度"的秘密。

## 协作不是开会,是"传纸条"的艺术

## 两条铁律:交接要格式化,验收要有标准

多智能体最容易做错的地方,是让 Agent 之间无限自由对话--结果它们聊了 50 轮还没开工。两条纪律能避开九成的坑:

1. **交接必须是格式化的工作产物**:研究员交给执行者的应该是大纲、要点清单、带链接的资料卡片,而不是一大段对话记录。因为下一个 Agent 要的"输入"是可执行的信息,不是聊天气氛;
2. **每个子任务必须有验收标准和最大重试次数**:比如"代码必须能跑通、文案必须覆盖五个要点",审查者对照标准放行,不过就打回,最多打回 N 次--防止两个 Agent 互相客套无限循环。

一句话:**好的多智能体系统像流水线,不像茶话会。**

## 什么时候该用，什么时候别用

多智能体不是免费的：每个 Agent 都要消耗 token，协调本身也有开销，而且调试难度不是线性增加而是指数增加——两个 Agent 的交互路径有 2 条，五个 Agent 的潜在交互路径就有 20 多条。出了问题，你不知道该骂谁。

- **该用**：任务天然分阶段（调研→写作→审查）、单上下文装不下、需要不同“专长”，且任务价值高到值得多花几倍 token；
- **别用**：简单任务。让一个 Agent 能写完的东西拆给五个，纯属给 token 捐款；
- **中间地带**：先用“一个 Agent + 分步执行”跑一遍，发现它确实在某一步“记不住、串了戏”，再把那一步独立成子 Agent——按痛点拆，不要按组织架构图拆。

判断口诀：**先问一个 Agent 行不行，再问拆开能不能各自隔离上下文**。两问都过，才值得上多智能体。

## 要点小结

- **多智能体协作(MAS)= 把复杂任务拆给分工明确的一组 Agent**;
- 价值在于上下文隔离与角色专注:研究员干净、执行者专注、审查者独立;
- 协作纪律:结构化交接、有限回合、明确验收--像流水线,不像茶话会;
- 用前两问:一个 Agent 行不行?拆开能隔离吗?
